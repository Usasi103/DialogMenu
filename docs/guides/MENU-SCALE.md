# 菜单整体缩放

“界面与语言 → 菜单缩放”提供 50%、75%、100% 三档。首次使用为 100%，保持原排版；缩小后，背景、文字、图标与按钮点击范围一起缩放。设置、任务、NPC 对话和首领画布共用这个玩家偏好。

选择立即生效，保存在玩家 PDC 的 `dialogmenu:menu_scale` 字段中；退出、重登和服务器重启后仍保留。语言、主题的旧字段继续兼容，不需要新数据库。

如果原菜单太大、点不到设置，输入 `/dmenu scale 75` 或 `/dmenu scale 50`。输入 `/dmenu scale 100` 恢复原尺寸；`/dmenu scale` 查看当前选择。

## 现有配置升级

更新插件和配套资源包后，已有菜单坐标、字号、贴图定义均保持原值。旧配置默认使用 100%；插件不会覆盖已有菜单文件。要给现有设置页增加入口，在 `Pages.appearance.Icons` 中加入以下控件，并把 `菜单缩放` 加入该页 `Layout`：

```yaml
菜单缩放:
  Type: dropdown
  Name: {zh_cn: "菜单缩放", en_us: "Menu scale"}
  Bind: menu-scale
  Options: {"50": "50%", "75": "75%", "100": "100%"}
```

`Bind` 自动负责读取、切换和保存，无需编写指令动作。选项键保留字符串 `"50"`、`"75"`、`"100"`，显示文字可以修改。下拉列表仍需预留展开空间，修改后执行 `/dmenu check` 和 `/dmenu reload`。

高级旧配置使用 `state: menu-scale` 和内置动作 `menu-scale:50` / `menu-scale:75` / `menu-scale:100`。

资源包需要同步 `dialogmenu_settings`、`dialogmenu_dialogue` 的 `font/scaled`、`dialogmenu_settings/textures/scaled` 和对应 GUI 焦点框着色器修改。CraftEngine 合并后重新构建并让玩家加载新包；只更新 JAR 无法显示新缩放字体。

## 适用范围

这是玩家手动选择的 DialogMenu 画布比例，不是分辨率自动检测。服务端不能读取窗口大小，也不会更改客户端全局 GUI 比例。50% 最适合窗口较小或全局 GUI 比例较大的情况；像素字体缩小后清晰度取决于客户端实际像素比例。

原生物品页、搜索输入框和原生底部按钮仍由 Minecraft 的 GUI 设置控制。内置画布资源支持上述三档；引用外部自定义字体且未编译缩放资源的画布会保持 100%，其他菜单继续使用已保存的比例。

当前开发版需要加载多套 Unicode 与字号资源，内存开销较大：独立原版测试客户端使用 3 GB Java 堆时，进程工作集约为 6–7 GB。低内存客户端尚未验证；切回 100% 不会卸载已加载的缩放字体。

## 开发维护

`tools/build_scaled_fonts.py <vanilla-client.jar>` 从已有字体及本地 26.2 客户端生成缩放字体和服务端字宽表；需要 Python 和 Pillow。增加或修改源字体、贴图时重新生成，随后构建插件并同步资源包。字体文件负责真实字形边界，因此按钮的点击坐标与绘制坐标一致，无需用着色器移动点击区域。
